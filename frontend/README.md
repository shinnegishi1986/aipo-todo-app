# 研修用 ToDo 管理アプリ

単一の HTML ファイルで動作する、Aipo 風の研修用途 ToDo 管理アプリです。外部バックエンドを必要とせず、ToDo、カテゴリ、ログインユーザー、ログイン状態などをブラウザの `localStorage` に保存します。

> **重要**: このアプリのログイン機能は研修・デモ用途です。ユーザー名とパスワードは HTML 内の初期配列およびブラウザの `localStorage` に平文で保存されます。実運用、社外公開、個人情報・業務データの利用には使用しないでください。

## 主な機能

- ログイン／ログアウト
- ページ再読み込み後も維持されるログインセッション
- 管理者によるローカルユーザーの追加・削除
- ToDo の追加、詳細表示、編集、削除
- 複数 ToDo の選択、一括完了、一括削除
- カテゴリ追加
- 組織（部署）選択に連動した担当者候補の絞り込み
- カテゴリ、組織、担当者、件名、進捗での検索
- 開始日・締切日の日付ピッカーと「指定しない」設定
- 優先度、進捗、メモ、公開設定、スケジュール表示の保存
- KPI 表示（全件数、進行中、完了、期限超過）
- 管理者による研修データの初期化
- ライト／ダークテーマ切替

## 起動方法

1. アプリの HTML ファイルを保存します。例: `index.html`
2. 保存した HTML ファイルをブラウザで開きます。
3. 初回はログイン画面が表示されます。
4. 研修用の初期アカウントでログインします。

ローカルファイルとして直接開くこともできますが、ブラウザごとの `localStorage` 制約を避けるため、簡易ローカルサーバーで開くことを推奨します。

```bash
python -m http.server 8000
```

起動後、ブラウザで `http://localhost:8000` を開いてください。

## 初期ログイン情報

| 表示名 | ユーザー名 | パスワード | 権限 |
|---|---|---|---|
| 研修管理者 | `admin` | `admin123` | 管理者 |
| テスト301 | `test301` | `test301` | 受講者 |

初期ユーザーは JavaScript の `DEFAULT_USERS` 配列に定義されています。

```js
const DEFAULT_USERS = [
  {
    id: 'user-admin',
    username: 'admin',
    password: 'admin123',
    displayName: '研修管理者',
    role: 'admin',
  },
  {
    id: 'user-test301',
    username: 'test301',
    password: 'test301',
    displayName: 'テスト301',
    role: 'trainee',
  },
];
```

HTML を編集して初期ユーザーを追加・変更することもできます。すでにブラウザにユーザー情報が保存されている場合は、`localStorage` に保存された内容が優先されます。

## 権限

| 機能 | 受講者 | 管理者 |
|---|---:|---:|
| ログイン／ログアウト | ○ | ○ |
| ToDo の追加・編集・削除 | ○ | ○ |
| ToDo 一括完了・一括削除 | ○ | ○ |
| カテゴリ追加 | ○ | ○ |
| テーマ切替 | ○ | ○ |
| ユーザー管理 | — | ○ |
| 演習データ初期化 | — | ○ |

## 管理者操作

管理者でログインすると、ヘッダーに以下のボタンが表示されます。

### ユーザー管理

「ユーザー管理」から、研修受講者または管理者アカウントを追加できます。

入力項目:

- 表示名
- ユーザー名
- パスワード
- 権限（受講者／管理者）

追加したユーザーは `localStorage` に保存されるため、同じブラウザ・同じオリジンでは再読み込み後も利用できます。

### 演習データを初期化

「演習データを初期化」を実行すると、以下を初期状態へ戻します。

- ToDo データ: 4件の研修用サンプルへ復元
- カテゴリ: 初期カテゴリへ復元
- 検索条件: すべて解除
- 選択中の ToDo: 解除

ユーザーアカウント、ログイン状態、テーマ設定は初期化しません。

## データ保存

このアプリはサーバーやデータベースを使用しません。主なデータはブラウザの `localStorage` に保存されます。

| localStorage キー | 保存内容 |
|---|---|
| `training-todo-app:users` | ユーザー情報（ユーザー名・平文パスワード・表示名・権限） |
| `training-todo-app:session` | 現在ログインしているユーザーのセッション情報 |
| `training-todo-app:todos` | ToDo データ |
| `training-todo-app:categories` | カテゴリ一覧 |
| `training-todo-app:filters` | 最後に使用した検索条件 |
| `training-todo-app:theme` | ライト／ダークテーマ設定 |

## ログインの仕様

1. アプリ起動時に `training-todo-app:session` を確認します。
2. セッションのユーザー ID が `training-todo-app:users` 内に存在する場合、自動ログインします。
3. ログアウトするとセッション情報のみ削除されます。
4. ユーザー、ToDo、カテゴリは残るため、次回は再ログインできます。

## サンプル ToDo

初期状態では、研修説明に利用できる 4 件のサンプル ToDo が表示されます。

- 新卒採用計画を確認する
- 顧客向け提案資料を作成する
- リリース前テストを実施する
- 月次経費を確認する

サンプルには、組織、担当者、カテゴリ、日付、優先度、進捗、公開設定、スケジュール表示の例が含まれています。

## 意図的な制約

この HTML は研修・デモを優先したクライアントのみの実装です。

- パスワードは平文で扱われます。
- HTML、開発者ツール、`localStorage` を閲覧できる利用者は認証情報を確認・変更できます。
- ブラウザのストレージを削除すると、ユーザー・ToDo・カテゴリ・セッションが消去されます。
- ユーザーごとの ToDo データ分離はありません。同じブラウザ・同じオリジンでは、ログインユーザーにかかわらず同じ ToDo データを参照します。
- 外部アクセス制御、HTTPS 強制、IP 制限、有効期限、SSO、監査ログは実装されていません。

## 実運用へ移行する場合

研修用の単一 HTML 実装を実運用へ移行する場合は、少なくとも次を実装してください。

1. HTTPS を常時有効化する
2. サーバー側認証を実装し、パスワードを安全なハッシュで保存する
3. HTTP-only / Secure / SameSite 属性付き Cookie または適切なトークンでセッションを管理する
4. ロールベースアクセス制御をサーバー側で実施する
5. ユーザー・講座・クラス単位で ToDo データを分離する
6. 管理者の初期化操作を監査ログとして記録する
7. 認証期限、パスワードポリシー、アカウントロックを導入する
8. バックアップ、復旧、削除ポリシーを整備する

## ブラウザデータを完全にリセットする方法

開発や研修の再実施などで、ログイン情報を含むすべてのローカルデータを削除する場合は、ブラウザの開発者ツールの Console で次を実行してください。

```js
Object.keys(localStorage)
  .filter((key) => key.startsWith('training-todo-app:'))
  .forEach((key) => localStorage.removeItem(key));

location.reload();
```

これにより、次回読み込み時に HTML 内の `DEFAULT_USERS` と初期サンプル ToDo が再作成されます。
